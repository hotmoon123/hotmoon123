# StitchLedger v0.2.2 update — local reminders + visual assets

This update combines the v0.2.1 local-workflow-reminder work with the v0.2.2 visual-asset system.

## Scope

It updates:

- the Expo mobile source, locked dependencies and generated Android/iOS project configuration;
- original app icon, adaptive Android icon foreground, launch mark, in-app mark and notification silhouette;
- opt-in local workflow/due-date reminder source;
- requirements, quality, notification and visual-asset documentation.

It does **not** modify `backend/`, `backend/data/`, or your current test accounts/orders. Do not copy an older database into another version; simply leave the existing database where it is.

## Before starting

1. Keep the backend terminal running if you want; it does not need an update.
2. Stop only the current Expo terminal with `Ctrl+C`.
3. Download `stitchledger-mobile-v0.2.2-update.zip` into `/home/caleb/Downloads/`.

## Safe update steps on Kali

```bash
cd /home/caleb/Projects/stitchledger-native
stamp=$(date +%Y%m%d-%H%M%S)
mkdir -p "/home/caleb/StitchLedger-backups/update-$stamp"

cp -a docs "/home/caleb/StitchLedger-backups/update-$stamp/docs-before-v0.2.2"

  -d /home/caleb/Projects/stitchledger-update-v0.2.2
```

The source copy command merges files and does not delete unlisted local files such as a local `.env`. The backup path printed in the command is your rollback copy.

## Install and run

```bash
cd /home/caleb/Projects/stitchledger-native/mobile
npm ci
npm run typecheck

export EXPO_PUBLIC_API_URL="http://192.168.1.51:8000"
npx expo start --go --lan --clear
```

Use the laptop's current LAN IP if it changes; `192.168.1.51` is the previously verified example. Scan the new QR code in Expo Go.

On iPhone, sign into Expo Go and Expo CLI with the same Expo account if Expo requests that. Allow local-network access when requested. The API backend must continue to run on the Kali laptop and both phones must remain on the same trusted Wi-Fi network.

## Test checklist — fictional data only

1. Confirm the new app icon/brand mark appears in the app header or sign-in screen.
2. In **Studio**, choose **Turn on daily 8:00 AM reminder** and respond to the phone’s notification-permission prompt.
3. Create a future fictional order and use **Remind day before** or **Remind on collection day**.
4. Confirm a notification tap opens the app/order for review; it must not change status or record a payment by itself.
5. Read `docs/VISUAL-ASSET-SYSTEM.md` and `docs/NOTIFICATIONS-DESIGN.md` for design and technical limits.

The exact adaptive app-icon masking, launch screen and notification appearance of a standalone app still require an owner-controlled development/production build and physical device test. Expo Go is the chosen current development host, not a signed release application.
