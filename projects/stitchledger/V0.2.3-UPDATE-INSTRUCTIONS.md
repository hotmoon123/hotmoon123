# StitchLedger v0.2.3 update — visual assets + daily order check-in

This combined update includes the visual assets, local reminders, and the requested daily status-progression workflow. It is designed for the current Android/iPhone Expo Go development route.

## What it adds

- Original app icon, Android adaptive icon foreground, launch mark, in-app mark and Android notification silhouette.
- Optional local daily 08:00 workflow reminder.
- A notification-driven **Daily workflow check-in** queue, also available from Today for manual testing.
- Explicit forward actions: **Booked → Cutting → Sewing → Ready → Collected**.
- **Overdue** as an automatic condition, not a replacement for the real work stage.
- **Keep current status for now**, **Remind me tomorrow**, and **Open full order** options.
- Existing safeguards remain: a notification tap itself changes nothing; the backend validates state/version; a Ready order cannot become Collected until its recorded balance is zero; cancellation requires the existing financial rule.

The update does not modify `backend/`, `backend/data/`, or your current test accounts/orders.

## Test the requested workflow — fictional data only

1. Open StitchLedger and select **Explore a private demo**.
2. Open **Today** → **Daily check-in**. You do not have to wait for 08:00 to test it.
3. Review the first order and choose its real next stage—for example, **Mark Cutting** for a Booked order.
4. Confirm the next order appears. Choose **Keep current status for now** or **Remind me tomorrow** to test those options.
5. For a Ready but unpaid order, confirm the app requires the remaining payment before **Mark Collected**.
6. In **Studio**, enable the daily reminder and grant OS permission. Its lock-screen content is generic; tapping it opens the check-in rather than changing data automatically.

Use only fictional data. Physical Android and iPhone checks are still required for actual scheduled local-notification delivery/tap behaviour. Expo Go supports this local-notification development test; a production remote-push service is separate future work.
