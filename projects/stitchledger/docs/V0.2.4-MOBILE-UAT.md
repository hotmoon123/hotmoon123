# v0.2.4 mobile UAT observation and regression plan

## Observed Android Expo Go evidence

The supplied device screenshots demonstrate that the mobile app reached its real order/payment and cancellation sheets on Android. This is meaningful physical-device evidence for the currently installed development source; it does not certify the newer v0.2.4 source until it is applied and retested.

## Observations

| ID | Observation | Risk | v0.2.4 response |
|---|---|---|---|
| UAT-01 | An empty payment/reference field produced raw backend validation wording: `note: String should have at least 1 character`. | User sees implementation terminology instead of a clear business instruction. | Make reason/reference visibly required, disable ordinary confirmation until amount and trimmed reason exist, and provide plain-language client validation. |
| UAT-02 | A cancellation rule warning could remain visible behind/reappear in a fresh cancellation confirmation. | Duplicated messages compete for attention and make the owner unsure which action is pending. | Clear stale error state before opening confirmation and prevent the background screen from duplicating an error owned by an active modal. |
| UAT-03 | The payment sheet contained explanatory copy, but a focused/scrolling modal can make the beginning of that copy less visible. | Critical instruction may be missed on a smaller screen. | Preserve the short required-reference cue beside the field/button; validate before submit. Future device review should confirm scroll/focus behaviour across keyboards. |

## Required regression test after update

Use only fictional data.

1. Open a Ready fictional order with a remaining balance.
2. Choose **Record payment**.
3. Enter an amount but leave **Reference / reason (required)** empty.
4. Verify the confirmation button is unavailable and no raw schema phrase appears.
5. Add a simple reference, for example `Balance received at fitting`, and record the test payment.
6. Attempt cancellation before/after appropriate genuine test refund entries as applicable.
7. Verify a fresh cancellation dialog has one clear warning, no stale background alert, and the result obeys the zero-net-payment rule.
8. Repeat with Cash, MoMo and Bank labels; no PIN, password or full account number should be entered.

## Acceptance boundary

The logic does not weaken backend validation. The server remains authoritative if a malicious, out-of-date or non-mobile client sends invalid data. The mobile change improves ordinary user experience while retaining server-side protection.
