# The one-page card

Print this. Everything else in this folder is the argument for these four columns.

---

## 1. Strength — the four that are real

Everything else is either a weakness or a claim.

| Strength | Why it is real | What would destroy it |
|---|---|---|
| **A published number that does not move** | five competitors all start at "from"; none publishes a final price | discounting one client quietly |
| **The client owns everything, by law** | Act 690 s.7 vests commissioned work in the commissioner — their contract may take it away; mine does not | registering a domain in my own name, once |
| **A verifier anyone can run** | 89 checks; the page fails to ship if it lies | adding a claim with no source |
| **A documented process** | six documents, published, for a real project | skipping the scope because the job was small |

**The one sentence:** *the only studio here whose price is final and whose work is
already yours.*

## 2. Logic — how the business actually works

```
     a stranger with a problem
              │
        [ 48h reply ]────────── no ──► they go quietly
              │ yes
        [ 45-min call, 6 questions ]
              │
      [ one-page scope + exclusions ]──── they won't sign ──► stop
              │ signed
           [ 50% clears ]
              │
         [ 30-hour build ]
              │
    [ 40% at demo · 10% at handover ]
              │
        [ handover sheet ]
              │
    [ 30-day warranty · bugs only ]
              │
   [ months 1–3: 1 hour/month, free ]
              │
      [ month 4: GH₵200–400/mo ]─── no ──► site stays up, I stop
              │ yes
       ┌──────┴──────┐
   the retainer    the case study
       │                │
   GH₵24,000/yr    the next client
   at 10 clients
```

**The two things this diagram says that the prose does not:**

1. **Every stage has an exit, and the exit is cheap.** The cost of saying no at the
   scope stage is two hours. The cost of saying no after the deposit is a
   relationship and a refund.
2. **The money is at the bottom of the funnel, not the top.** A GH₵1,500 build is
   the entry ticket to a GH₵200/month relationship, which is worth GH₵2,400 a year
   — **more than the build.** Price the build as a door, not as a job.

## 3. Process — the only three that matter daily

| When | The process | The test that it happened |
|---|---|---|
| **Morning** | open messages, answer all, quote what can be quoted, say no to what cannot | zero unanswered threads older than 48h |
| **Middle** | the build block, phone off, one job only | a working preview by the end of it |
| **Afternoon** | support and changes; name each as bug or change before touching it | nothing changed without the client knowing which it was |

**The weekly one:** Friday, two hours — reconcile, file, invoice, back up, write
the plan notes. **The monthly one:** close the month, move 3% to tax, review the
pipeline.

---

## 4. Fundamental — the five rules, in priority order

When two conflict, the higher number wins.

| # | Rule |
|---|---|
| **1** | Never write a number I cannot hold |
| **2** | The client owns the keys — domain, hosting, code, content |
| **3** | Say what is not included before saying what is |
| **4** | Only claim what was measured |
| **5** | One named person answers, and it is me |

**Rule 1 is above rule 5 for a reason:** it is better to answer slowly than to
answer with a number that moves.

## 6. If everything is on fire

In this order:

1. **Tell the client before they find out.** A named mistake is a service; a
   discovered one is a betrayal.
2. **Fix what breaks the client's business first,** not what is most interesting.
3. **Do not touch the tax money.** It was never yours.
4. **Write down what happened** in the incident log, while it is fresh.
5. **Ask whether a rule was broken** — and if it was, which one. That is the whole
   post-mortem.
